# 右键菜单架构（v6）

> **状态：** 已落地（2026-08-20）  
> **范围：** 工作台内所有场景的上下文菜单（文件清单、日志 Tab、日志行；后续终端等只加场景表）  
> **ADR：** ADR-v6-019（本文 §5；主表见 `架构设计-v6.md` §14）

---

## 0. 结论

右键菜单是壳级浮层，不是各页面自己的一份 `YoContextMenu`。

引擎在 `@yohu/ui`（与 keymap 同级）。场景表按模块收口到 `menu.ts`。`@yohu/app` 只挂唯一 `YoContextMenuHost`。模块禁止再渲染 `YoContextMenu`，禁止再自管 `menu` 坐标 signal。

业务 store 不进 `@yohu/ui`。模块之间仍然零 import（ADR-v6-012）。

---

## 1. 为什么不能分散

分散时每个 View 各自：

- `createSignal({ x, y })` + 本地 `menuItems()` + 一份 `<YoContextMenu>`
- 无法保证全局同时只开一个
- 切模块后菜单还能点到已卸载页面的闭包
- 条目与快捷键（`keys.ts` 的 Ctrl+C 等）对不齐

keymap 已经证明同一模式：共享宿主 + 页面只交绑定表。菜单走同一分层。

---

## 2. 分层

```text
L0 呈现     YoContextMenu（受控；Host 专用）
L1 条目     YoMenuItem（id / label / danger / disabled）
L2 场景     defineContextMenu({ id, items, onSelect })
L3 会话     openContextMenu(scene, { x, y, ctx })  全局同时一份
L4 宿主     YoContextMenuHost 挂在 AppLayout；Portal → body
```

```text
模块 View          只负责：右键坐标、把当前状态打进 ctx
    │  openContextMenu(filesListMenu | logsRowMenu | …)
    ▼
@yohu/ui context-menu
    define / open / close / 视口夹紧
    YoContextMenuHost → YoContextMenu
    │
    ▼
模块 menu.ts       场景 id、条目、onSelect 分发（不碰 store）
```

页面打开时把动作以函数放进 `ctx`（`copy` / `rename` / `remove`…）。场景表保持纯描述，可单测。

---

## 3. 场景目录

| id | 模块 | 触发 | 条目 |
|----|------|------|------|
| `files.list` | `@yohu/module-files` | 清单行 / 空白处 | 新建文件、新建目录、下载、复制路径、删除 |
| `logs.tab` | `@yohu/module-logs` | 会话 Tab | 重命名、复制会话、关闭其他 |
| `logs.row` | `@yohu/module-logs` | 日志行 | 复制（与 Ctrl+C 同一 `copyLogText`） |

新增场景：在该模块加 `menu.ts` 条目 → View 里 `openContextMenu`。不要在 View 里写死 `items` 数组。终端等后续模块同样只加场景，不新挂组件。

---

## 4. API 契约

```ts
const logsRowMenu = defineContextMenu<LogsRowMenuCtx, "copy">({
  id: "logs.row",
  items: (ctx) => [{ id: "copy", label: "复制", disabled: !ctx.canCopy }],
  onSelect: (id, ctx) => {
    if (id === "copy") ctx.copy();
  },
});

openContextMenu(logsRowMenu, {
  x: event.clientX,
  y: event.clientY,
  ctx: { canCopy: selectedKeys().size > 0, copy: copySelected },
});
```

规则：

1. 场景 `id` 用 `模块.对象`（`files.list`、`logs.row`）。
2. 同时只开一个；后开覆盖先开。
3. 切模块、切日志会话、页面卸载都 `closeContextMenu()`。
4. 落点按视口夹紧（宽 `Layout.MenuMin`，高按条目估算）。
5. Host Portal 到 `document.body`，避免祖先 `transform` 打断 `position: fixed`。
6. 测试用 `createContextMenuController()`，不要打全局实例。

禁止：

- 模块 JSX 出现 `<YoContextMenu>`
- `@yohu/ui` 引用 `fileStore` / `logStore`
- 模块互 import 对方的 `menu.ts`

---

## 5. ADR-v6-019

**决策：** 右键菜单引擎放在 `@yohu/ui`，壳挂唯一 Host；场景表按模块收口。

**否决：**

- 新建 `@yohu/module-context-menu` 工作台模块（没有导航位，且会逼模块互 import）
- 在 `@yohu/app` 硬编码全部条目（壳会依赖三模块 store，破坏依赖方向）
- 继续各 View 自挂一份（无法保证单实例与卸载安全）

**后果：** 新右键能力 = 改该模块 `menu.ts` + 一处 `openContextMenu`。呈现/夹紧/Esc/外点关闭只改 `@yohu/ui`。
