# ADR-v6-028 — 投屏多平台原生后端

- **状态：** 已接受
- **日期：** 2026-09-04
- **补充：** [ADR-v6-024](ADR-v6-024.md)（Windows 实现仍是进程内 MF）、[ADR-v6-026](ADR-v6-026.md)、[ADR-v6-027](ADR-v6-027.md)

## 背景

024 把直播解码钉在进程内系统 API，禁止 `ffmpeg.exe`。调研结论：

1. **无 FFmpeg 的硬解存在，但没有一份跨 OS 的原生 ABI。** Windows = Media Foundation + DXVA；macOS = VideoToolbox + IOSurface；Linux = VA-API / Vulkan Video。FFmpeg 的价值是把这些收成一套，不是硬解本身。
2. **Yohu 本期只交付 Windows 10/11 x64。** 需求与 `layers.md` 未改。但解码/呈现今天用 `#[cfg(windows)]` 整段掏空，其它目标直接 `error!`，以后补平台只能拆 HWND 细节。
3. **零拷贝要求解码器和呈现器共享 GPU 设备。** 纹理类型（`ID3D11Texture2D` / `CVPixelBuffer` / DMA-BUF）不能进 core，也不能做成与 OS 无关的 `Vec<u8>` 默认路径。

## 决策

1. **永远不走 FFmpeg。** 禁止 `ffmpeg.exe` 管道、禁止链 `libavcodec` / `ffmpeg-next`、禁止 `LoadLibrary` 进直播路径、禁止用 FFmpeg 的 d3d11va/videotoolbox/vaapi 封装「假装原生」。macOS / Linux 后端未实现时保持编译通过并返回明确错误，**禁止用 FFmpeg 填坑**。
2. **编译期选后端，不是运行时插件。** 与 ADR-v6-012 一致。`cfg(windows)` → Media Foundation；`cfg(target_os = "macos")` → VideoToolbox 占位；`cfg(target_os = "linux")` → VA-API 占位。禁止按 GPU 品牌再分 NVDEC / AMF / oneVPL 三套（系统硬解已经吃到同一块 DXVA/VT/VA）。
3. **分层不变。** `yohu-mirror` 只解复用 Annex-B 到 `FramePipe`（已与 OS 无关）。解码、嵌入式表面、铬层绘制仍在壳 `mirror_present`（ADR-v6-005：GPU/窗体不进 core）。IPC / UI / 占用规则（026/027）不按平台分叉。
4. **契约在壳内，GPU 类型是关联类型。**

   ```text
   Caps { id, hevc }
   AnnexBDecoder { Picture, Bind; open / feed / drain }
   Cmd { Layout, BindPipe, UnbindPipe, Screenshot, Shutdown }
   spawn_surface(owner: isize, …) -> Sender<Cmd>
   ```

   `owner` 是宿主窗句柄：Windows = `HWND`，macOS 预留 `NSView*`，Linux 预留父 widget。`Bind` 是本后端把解码器接到 GPU 设备的句柄（Windows = `IMFDXGIDeviceManager`）。`Picture` 不得在契约层写成 packed NV12；CPU NV12 只允许作为该后端自己的软解回退。
5. **Windows 实现仍是 024。** 硬件 MFT + DXGI 设备管理器 + Video Processor + `WS_CHILD` HWND + DirectComposition。HEVC 能力来自 `Caps.hevc`（本机 MFT），不是 UI。
6. **macOS / Linux 本期不交付像素。** 占位模块必须：实现 `AnnexBDecoder`（`open` 返回未实现）、`probe()` 给出稳定 `id` 且 `hevc=false`、`spawn_surface` 能收下 `Cmd` 并让截图失败信息可读。产品行为：非 Windows 构建可编译；`mirror.start` 后无画面，错误指向「该平台后端未实现」。
7. **共享、与 OS 无关的部分** 留在 `mirror_present` 根：`Cmd`、`scale`（contain / letterbox）、舞台文案推导。几何跟随、D3D/D2D/MF 只在 `windows/`。

## 管道

```text
设备 MediaCodec Annex-B
  → ADB reverse | forward
  → yohu-mirror 解复用 + FramePipe        ← 全平台同一 crate
  → 壳 AnnexBDecoder（编译期后端）
       Windows : MF 硬件 MFT + DXGI
       macOS   : VideoToolbox（预留）
       Linux   : VA-API（预留）
  → 壳表面 Present（编译期后端）
       Windows : HWND + DComp + VP
       macOS   : NSView / Metal（预留）
       Linux   : 嵌入式 widget（预留）
```

## 否决

FFmpeg（CLI 与库）、运行时插件选解码器、core 里出现 DXGI/Metal/VA、默认 CPU packed NV12 跨进程拷、用 WebCodecs 当「跨平台后端」、用 Vulkan Video 替换本期 Windows 路径、为预留接口先写空的 `yohu-mirror-present` crate。

## 后果

本期产品仍只保证 Windows。其它目标的工作是填 `macos` / `linux` 模块，而不是改 `FramePipe` 或 UI。HEVC 探测走 `PresentHost` ← `Caps`，命令层不必知道 MFT。
