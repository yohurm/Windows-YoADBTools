# ADR-v6-023 — 投屏画质与包通道

- **状态：** 已接受
- **日期：** 2026-09-02
- **修订：** 编码按投屏协议；实测 fps 进状态栏；二进制 Channel、display×DPR 绘制

## 背景

内嵌投屏若把 canvas 位图设成视频分辨率再交给 CSS 缩放，Windows 高 DPI 上二次滤波发糊；编码包若走 JSON 事件总线，高码率时易丢最新包（含 IDR）。WebView2 对手机原分辨率 High@L5.1 硬解常无输出（DXVA 保证线 1920×1088）。

## 决策

1. **编码按投屏协议。** USB：长边 1920、8 Mbps、`max_fps=0`（不传 `KEY_MAX_FPS_TO_ENCODER`）。`connection` 以 `tcp:` 开头时本会话用 wifi：1024 / 2 Mbps / 30，并默认 ADB forward。用户改过质量则不再自动覆盖。无「自定义」协议；改长边/码率/帧率只改参数。`max_size=0`（原始）编码器封顶 1920。本期仍只发 H.264；`video_codec` 留位。
2. **编码包退出 JSON 事件总线。** `AppEvent::MirrorPacket` 删除；`mirror/state` 仍必达。`mirror.start` 带 Tauri `ipc::Channel`；core 只暴露 `FramePipe`（有界 8 帧：先丢 delta，不丢 config）。壳泵二进制帧（32 字节头 + payload）。
3. **绘制为 display × devicePixelRatio。** WebGL2（缩小 LINEAR/bicubic，整数倍放大 NEAREST），失败回退 2D `imageSmoothingQuality=high`。保留 `lastFrame`，ResizeObserver / DPR 变化重绘。截图按视频分辨率。
4. **实测 fps 在状态栏右槽**（1s 窗口已绘帧），不是画面角标，也不是质量栏的编码器上限。

## 后果

- `@yohu/api` 的 `mirror.start` 必须传入 `Channel`；编码包不进事件总线。
- 无线 pairing / `adb connect` 不在本期；管道已可按 `tcp:` 切换协议。

## 否决

拉起 `scrcpy.exe`、独立 OS 窗口、引入 `@yume-chan/scrcpy-decoder-*`、本期 H.265、WebGPU、`--disable-frame-rate-limit`、默认 120 fps。
