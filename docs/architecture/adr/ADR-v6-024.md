# ADR-v6-024 — 投屏原生呈现

- **状态：** 已接受（2026-09-02 修订：进程内 MF，废弃 ffmpeg.exe 管道；2026-09-04：跨 OS 选择见 028）
- **日期：** 2026-09-02
- **取代：** [ADR-v6-023](ADR-v6-023.md)（WebCodecs / Channel / display×DPR canvas）
- **跨 OS：** Windows 实现细节以本文为准；后端选择与 macOS/Linux 预留见 [ADR-v6-028](ADR-v6-028.md)

## 背景

WebView2 内 WebCodecs 对手机原分辨率常无输出。首版「壳内 FFmpeg」被实现成 **sidecar `ffmpeg.exe` stdin/stdout 管道**。日志证明这条路不能做直播解码：

1. CLI 选项排错（如 `-fps_mode` 放在 `-i` 前）→ 进程 EXIT -22 → stdin「管道正在被关闭」。
2. `spawn` 成功被当成解码器就绪；stderr 默认 `debug` 不可见。
3. 写失败即 `decoder=None`，每帧重启 → 重启风暴，从未 `mirror/painted`。
4. 同线程 `read_exact` NV12 会堵死 IDR。管道边界无法做零拷贝 D3D 纹理。

设备侧（push / 隧道 / Live / Annex-B）在 700ms 内是通的。卡在「等待画面」是 **壳解码层架构错误**，不是 scrcpy。

## 决策

1. **视频不进 JS。** `yohu-mirror` 只解复用 Annex-B 到 `FramePipe`。Windows 上壳 `mirror_present` 用 **进程内 Media Foundation** 解出 NV12（其它 OS 见 028）。Codec config 不是画面，只作为 IDR 前缀送入；硬件 MFT 优先。异步 MFT 按 `NeedInput`/`HaveOutput` 事件泵。禁止 `ffmpeg.exe` 管道、禁止链 `libavcodec`、禁止 `LoadLibrary` 进直播路径、禁止 `scrcpy.exe`。
2. **编码参数唯一数据源是 `yohu-domain::mirror`。** UI 不复制 USB/WiFi 表。`mirror.start` 只传 `serial/control/connection/session_quality_touched`；壳用当前 `AppSettings` 调 `start_encode` / `start_force_forward`。本机无 HEVC MFT 时 USB 改 H.264（同一长边/码率）。
3. **控制面唯一数据源。** Live 尺寸/编码只信 `mirror/state`（禁止 `mirror.status` 轮询对账，且不保留该命令）。出画只信 `mirror/painted`。`FramePipe` 永久保留最后一份 config，IDR 优先于 delta，禁止为腾容量丢掉最后的 config。**呈现线程始终从 `FramePipe` ingest**（`visible=false` 只跳过 Present，避免 layout 未到时队列撑死）。禁止再泵进无界通道。
4. **进程内表面。** 画面 HWND 是主窗的 **WS_CHILD**（客户区坐标），不是屏幕坐标 `WS_POPUP`。拖动主窗由 USER32 带着子窗走，禁止 JS `screenX` 轮询跟窗。几何见 [ADR-v6-027](ADR-v6-027.md)：`mirror.layout` 报舞台列 avail 客户区矩形；WebView 舞台是透明洞；HWND 铺满 avail；可见占用卡片是 DirectComposition clip（会话 contain）。UI **禁止**运行时 `containInZone`。占用 fill↔contain 走 `IDCompositionAnimation`；主窗改尺寸在 owner `WM_WINDOWPOSCHANGING` 里瞬时跟 HWND。呈现线程只解码 / Present / clip，**禁止** `SetWindowPos`。`SetWindowPos` **禁止** `SWP_NOCOPYBITS`；跨线程用 `SWP_ASYNCWINDOWPOS`。圆角与占用盒裁在 DirectComposition visual（`IDCompositionRectangleClip` + `IDCompositionAnimation`），**禁止** GDI `SetWindowRgn`。`CreateSwapChainForComposition` 强制 `DXGI_SCALING_STRETCH`（API 要求，且 `SetFullscreenState` 非法）。子窗尺寸只随 avail 变；呈现线程 `ResizeBuffers` 并立刻 Present。解绑 RTV，**不要** `SetContent(None)`。`Present(0)`。`mirror.layout` 为 async + 发送即忘。低于 64 物理像素的 layout 丢弃。
5. **启动预热。** 扫描成功后 warmup（跳过重复 push、预挂隧道）。Live 后短时无媒体包则 `KEYCODE_WAKEUP`。
6. **实测 fps** 为壳 Present 计数，经 `mirror/painted` 进状态栏。
7. **呈现线程不得被 DXGI 消息泵堵死。** `PeekMessage` 只抽本 HWND；`WM_PAINT` 只 `ValidateRect`。帧积压只发生在 `FramePipe`（8 帧，先丢 delta）。每批 Present 最后一帧。交换链为 `CreateSwapChainForComposition` + `FLIP_SEQUENTIAL` + `PREMULTIPLIED` + `SCALING_STRETCH`；HWND 创建即带 `WS_EX_NOREDIRECTIONBITMAP`。`Present(0)`。`ResizeBuffers` 按偶数像素合并，禁止侧栏每像素重建；缩放期间 stretch 上一帧。禁止把 64ms 静默当成产品行为、禁止 `hwnd_is_contained` 挡 Present。
8. **PC 端对齐厂商多屏协同。** 华为/Phone Link/OPPO 跨屏都是：手机 MediaCodec 硬编 → 电脑 **DXVA/D3D11 硬解** → **Video Processor** 做 BT.709 full 色彩与缩放 → DXGI Present。壳内把 `IMFDXGIDeviceManager` 交给硬件 MFT，解码帧留在 GPU；禁止默认走 CPU packed NV12 + 双线性 shader（那是糊和卡的根因）。无硬解时仍可用 VP 缩放软解 NV12。

## 管道

```text
设备 MediaCodec Annex-B
  → ADB reverse | forward
  → yohu-mirror 解复用 + FramePipe（sticky config）
  → 壳 MF 硬件 MFT（DXGI 设备管理器）
  → D3D11 Video Processor（BT.709 full → RGB）
  → WS_CHILD 铺满 avail + DirectComposition clip（占用卡片 contain）
```

## 否决

`ffmpeg.exe` 直播解码、独立 scrcpy 窗、WebCodecs/WebGL、`@yume-chan/scrcpy-decoder-*`、本期 libplacebo/mpv、wry DirectComposition、音频/录像/多设备同时投屏、默认 120 fps、UI 再维护一份编码表、`waitUntilLive` 轮询。
