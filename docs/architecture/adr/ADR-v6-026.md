# ADR-v6-026 — 投屏舞台像素所有权

- **状态：** 已接受
- **日期：** 2026-09-03
- **补充：** [ADR-v6-024](ADR-v6-024.md)（Windows：进程内 MF + HWND）、[ADR-v6-028](ADR-v6-028.md)

## 背景

024 把视频放在主窗 `WS_CHILD` + `WS_EX_NOREDIRECTIONBITMAP` + DirectComposition 交换链上，帧不进 JS。空态/加载仍画在 WebView overlay 里，并用 `painted()` 与 HWND **XOR**：出画卸掉 overlay，停止再拆 HWND、指望 WebView 把空态画回来。

这两层抢同一块客户区。NOREDIRECTIONBITMAP 子窗由 DWM 单独合成，不进入 WebView backing。`DestroyWindow` / `SW_HIDE` 之后 WebView2 往往不再栅格化曾被挡住的矩形，内容面板变白板。首次进入从未创建 HWND，所以空态看起来正常。在 JS 里重挂 overlay 或延时 invalidate 解决不了所有权。

编码停止（`mirror.stop`、`mirror/state=stopped`）还被误绑成拆 HWND（`PresentHost::detach` → `Cmd::Stop` → `DestroyWindow`），把控制面会话和舞台表面当成同一个对象。

## 决策

1. **舞台像素只由 HWND 持有。** 投屏页可用区可见且 ≥64px 时创建表面；空态 / 加载 / 暂停 / 视频都画在这块表面上。WebView 只留透明占位上报几何，不再画舞台内容。
2. **两段生命周期。** HWND ↔ 舞台可见性（进投屏页 `mirror.layout visible=true`，离开页或进程退出 `visible=false` / `shutdown`）。解码管道 ↔ `mirror.start` / `mirror.stop`（`BindPipe` / `UnbindPipe`）。停止投屏只解绑管道并改画 chrome，禁止拆窗。
3. **铬层文案与颜色在壳。** 空态 / 加载 / 暂停由 HWND Direct2D/DirectWrite 绘制。产品文案与色值在壳内，不经 `mirror.layout` 传 title / ARGB。UI 只报 avail 与会话旗标（含 `dark` / `failed` / `error` / `has_device`）。
4. **几何。** 占用见 [ADR-v6-027](ADR-v6-027.md)。`mirror.layout` 报舞台列 `.yohu-mirror__avail` 客户区物理矩形 + 会话旗标。HWND 铺满 avail；会话 clip 按 FramePipe 编码尺寸 `contain_in_zone`；idle / failed / unbound clip 铺满 HWND。编码尺寸不来自 UI；present 在 `stop` 后保留上次尺寸。占用 fill↔contain 走 `IDCompositionAnimation`；主窗改尺寸瞬时跟 HWND。禁止 UI 运行时 `containInZone`、禁止 CSS 占用宽高过渡、禁止 `video_width` / `stroke_px`、禁止 `WS_EX_TRANSPARENT` 切换。缩放只改 clip；avail 变化才 `ResizeBuffers`。离开投屏页拆 HWND 时对主窗 `InvalidateRect`。
5. **显示。** 几何宿主在算出位置后才 `SetWindowPos`（禁止持锁跨调用；禁止 `SWP_NOCOPYBITS`；跨线程用 `SWP_ASYNCWINDOWPOS`）。`ShowWindow` 只在 chrome 或视频 Present 成功之后，避免空 DComp 交换链先闪一帧。
6. **否决。** 出画期间卸 overlay、停止后再请 WebView 接管；用 timeout/`InvalidateRect` 当产品行为；WebView2 `Bounds` 挖洞（单矩形盖不住中间舞台）；为 chrome 再开一个 WebView。

## 后果

`PresentHost` 主窗至多一块舞台。`detach` 语义改为 unbind。IPC 见 `ipc.md`；呈现见 `modules/mirror.md`。
