# ADR-v6-025 — 设备目录与运行时状态分流

- **状态：** 已接受（as-built）
- **日期：** 2026-09-03

## 背景

`adb devices -l` 只给出存在性（serial / 型号 / online·unauthorized·offline / 连接方式）。夜览、电量、SDK、亮屏等必须再跑 `dumpsys` / `getprop`。这些曾散落在投屏页 2s 轮询 `device.nightMode`，与设备栏目录不是同一源，模块也无法复用。

## 决策

两层、一个 UI 投影：

| 层 | 唯一写入 | 读取 | 内容 |
|----|----------|------|------|
| **目录** | `device.refresh`（启动预热 / 手动 / 自动刷新）→ `last_devices` | `device.list`、`devices/changed`、`require_online` | `DeviceInfo` |
| **运行时状态** | `DeviceStatusHub`（每台 Online 一路，2s 采样；内容变才推） | `device.status`、`device/status` | `DeviceStatus` |

- Hub 在 `yohu-adb`（运输 + 解析），不是新 capability crate，也不是 `registerModule` 工作区模块。
- 只对 **Online** serial 开采样；离开 Online 集合（拔线或 unauthorized/offline）则停采样并丢缓存。同一批 `went_offline` 停采集/投屏并推 `device/offline`。
- 字段缺省为 `None`：机型或 Android 版本差异不得让整份快照失败。
- 变更才发 `device/status`（`try_send` 可丢）；`generation` 仅在内容变化时递增。UI 丢事件后用 `device.status` 对账。
- **禁止** 模块或 DeviceRail 自己 `setInterval` 打 dumpsys。投屏月亮/太阳读 `DeviceSession.deviceStatuses`，写走 `device.setNightMode`（经 Hub 更新缓存并推事件）。
- 删除 `device.nightMode` 与 `DeviceNightMode`：深浅色只是 `DeviceStatus.night`。工作台 `settings.theme` 仍与设备 uimode 无关。
- 一次 shell 脚本采齐分段输出，避免每字段一次 `adb shell`。

## 非目标

- 不把 capture / mirror / transfer 会话塞进 `DeviceStatus`（那些已有各自 generation 与事件）。
- 不在 `DeviceInfo` 上堆 dumpsys 字段（目录扫描必须快、失败不改表）。
- 不新增侧栏「设备模块」Tab。

## 后果

`DeviceSession` 增加 `deviceStatuses`。设备栏可展示电量/系统版本。IPC 见 `ipc.md`；模块说明见 `modules/device.md`。
