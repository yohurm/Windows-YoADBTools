## 3. Findings（当前仍开）

### P0

#### [P0-1] logcat ConsumeLoop 跨世代污染并误关新 Channel

- **位置：** `LogcatCaptureService.ConsumeLoopAsync`（约 99–140）
- **证据：**
  - `TryWrite` / `TryComplete` 操作的是**字段** `_lines`，不是本世代捕获的 Channel；
  - `finally` **无条件**调用 `CaptureStopped`（即使 `_process` 已是新进程）。
- **场景：** Stop 后立刻再 Start（或旧循环 finally 晚于新 Start）：
  1. 旧循环向新 `_lines` 写入；
  2. 旧 finally 把新 Channel `TryComplete`；
  3. `CaptureStopped` → VM `OnCaptureStopped` 把新一轮 `IsCapturing` 打回 false，后台任务标 Failed。
- **影响：** 停后再采不稳定；行流提前结束；UI 与真实进程不一致。
- **修复：** ConsumeLoop 捕获本世代 `ChannelWriter` + generation id；仅本世代 Complete；仅当仍是本世代进程时触发 `CaptureStopped`。

#### [P0-2] `StartAsync` 失败留下未 Complete 的 Channel，Drain 永久卡死

- **位置：** `LogcatCaptureService.StartAsync`（约 49–64）；`LogAnalyzerViewModel.DrainLoopAsync`（约 165–200）
- **证据：** 在 `await ExecuteStreamingAsync` **之前**已把 `_lines` 换成新 Channel；若 await 抛错，新 Channel 永不 Complete；Drain 的 `WaitToReadAsync` 永不返回，无法切到后续世代。
- **影响：** 一次启动失败（adb 不可用/设备拒绝）后，之后即使 Start 成功，界面也可能永远无新行。
- **修复：** Start 失败时回滚：Complete 该世代 Channel、Dispose `_cts`、恢复空闲状态；或先创建进程成功再切换世代。

### P1

#### [P1-1] 切换设备不停采

- **位置：** `LogAnalyzerViewModel.StopIfDeviceGone`（约 226–230）
- **证据：** 仅当 `ActiveDevice is null` 才 Stop；A→B 切换时继续采 A，状态栏却显示 B。
- **修复：** 记录采集中的 Serial；焦点变化且 Serial 不同则 Stop（或自动切到新设备重采，需产品确认）。

#### [P1-2] 设备掉线时 `ActiveDeviceChanged` Action 不触发

- **位置：** `DeviceSessionHub.OnDevicesRefreshed`（约 125–129）
- **证据：** 掉线只 `_bus.Publish(new ActiveDeviceChanged(null))`，**不**调用 `ActiveDeviceChanged?.Invoke()`。LogAnalyzer 只订阅 Action（约 L82）。
- **影响：** 刷新导致焦点清空时，LogAnalyzer 不一定停采（只能赌 adb 进程退出）。
- **修复：** `activeLost` 时同步 `ActiveDeviceChanged?.Invoke()`；或模块改订阅总线（统一一种通道更佳）。

#### [P1-3] 文件管理快速导航：`IsBusy` 吞掉刷新 + 无加载世代

- **位置：** `FileManagerViewModel.RefreshAsync` / `NavigateTo` / `LoadDirectoryCoreAsync`（约 75–140）
- **证据：** `RefreshAsync` 在 `IsBusy` 时直接 return；`NavigateTo` fire-and-forget `RefreshAsync`；`LoadDirectoryCoreAsync` 注释写「自身防重入」但**无**加载序号/锁。
- **影响：** 连续进目录时路径栏已是 B、列表仍是 A；交错完成时旧结果可覆盖新目录。设备切换中若正忙也会漏刷（H1 残留）。
- **修复：** 拆分传输锁与加载锁；为每次加载分配 generation，过期结果丢弃；导航始终排队或取消上一次 List。

#### [P1-4] 终端执行未挂 `ShutdownToken`

- **位置：** `TerminalViewModel` 调用 `ExecuteAsync` 不传 CT；`AdbTerminalModule.DisposeAsync` 为空
- **影响：** 关窗后长命令仍可能跑到超时；与 FileManager/LogAnalyzer 已挂退出信号不一致。
- **修复：** 执行链路入 `IAppLifecycle.ShutdownToken`；或 Dispose 时取消进行中的执行。

## 6. 架构债务（会导致故障）

1. **Logcat 世代状态机不完整：** Channel / process / CaptureStopped / VM `IsCapturing`/`_taskId` 未绑定同一 generation → P0/部分 P1 根因。  
2. **Session 事件双通道且掉线只发一侧** → 订阅错误通道即静默失效。  
3. **FileManager 单一 `IsBusy` 兼传输与加载** → 导航与操作互相饿死（H1 只修了操作后半段）。  
4. **长任务取消策略不统一：** 传输/logcat 已挂 Shutdown；终端未挂。  
5. **仓库残留 `src/FactoryHelper/`**（未进 sln）→ 审查/搜索易混淆，建议删除或归档。
