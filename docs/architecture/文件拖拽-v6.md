# 文件拖拽架构（v6）

> **状态：** P1–P3 已落地（2026-08-20）  
> **范围：** Windows Explorer ↔ 当前设备文件夹，拖入/拖出文件或目录  
> **调研：** YoAgentDocs `research/by-stack/client-runtime/`（ADB-Explorer、scrcpy、wry、drag-rs）  
> **ADR：** ADR-v6-018（本文 §8；主表见 `架构设计-v6.md` §14）

---

## 0. 结论

Windows 资源管理器就是本机一侧。Yohu 文件页只展示设备。不要做双栏本机树。

拖入和拖出是两条 OLE 角色，不能合成一个「拖拽模块」：

| 方向 | OLE 角色 | 数据何时进 `TransferRunner` |
|------|----------|------------------------------|
| 拖入 | wry 已是 `IDropTarget`（`CF_HDROP`） | drop 当时：本机路径已在磁盘 |
| 拖出 | 壳实现虚拟 `IDataObject` | Explorer **GetData 之后**：才 `adb pull` |

默认 **Copy**。v1 不做 Move（源删除时序无法从 Explorer 可靠确认）。`SafetyRoot` 仍只在 core。OLE 只在 `app/yohu-app`，不进 core、不进 `commands/*` 业务分支、不进 Solid。

---

## 1. 设计前链路（现状）

```text
资源管理器 ──（断开）── 文件页
                           │
FileView  开/存对话框（plugin-dialog）
  → fileStore.push/pull(local, name)
  → IPC files.push / files.pull
  → commands/files.rs spawn_transfer（发号、任务中心、CancellationToken）
  → TransferRunner
       push：local 可为文件或目录（目录交给 `adb push` 递归）
       remote：SafetyRoot.check_descendant
  → adb push/pull
  → transfer.progress（Running 可丢；终态必达）
```

缺口在三跳：

1. 资源管理器路径进不了 `fileStore`（无 drop）。
2. 设备条目出不去资源管理器（无 `IDropSource`）。
3. `TransferRunner` 拒绝目录，对话框也只选单文件。

对话框路径保留。拖拽是同一传输引擎的新入口，不是第二套 push/pull。

## 2. 目标分层

```text
UI  @yohu/module-files
    命中测试 / 拖入高亮 / dragstart preventDefault
    不解析 FORMATETC，不拼 adb argv
        │  @yohu/api（已有 push/pull；新增 files.dragOut）
        ▼
app/yohu-app
    commands/files.rs     薄转发（反序列化 → 发号/转发）
    dnd/                  Windows OLE 源（仅拖出）+ 拖出临时目录
        │
        ▼
yohu-files::TransferRunner   文件或目录；进度/取消/终态
yohu-domain::SafetyRoot      远端路径唯一校验
yohu-adb                     sidecar adb.exe
```

不新开 crate。不引入 `drag` / `tauri-plugin-drag`（载荷是本机 `CF_HDROP`，解决不了设备文件）。

### 2.1 各层职责

| 层 | 做 | 不做 |
|----|----|------|
| `FileView` / `fileStore` | 模块挂载期间听 `tauri://drag-*`；用坐标/hover 决定目标文件夹；多文件逐条 `push`；行 `dragstart` → `files.dragOut` | OLE；读 `DataTransfer.files` 当主路径；绕过 IPC |
| `@yohu/api` | 类型化 `files.dragOut` | 业务 |
| `commands/files.rs` | `require_online` + 发号；`dragOut` 转到 `dnd` | `IDataObject` / `DoDragDrop` |
| `yohu-app/dnd` | 虚拟文件 `IDataObject` + `IAsyncOperation`；主线程 `DoDragDrop`；临时目录生命周期 | `SafetyRoot`；自己 spawn adb |
| `TransferRunner` | `adb push/pull` 文件**或**目录；取消时 pull 清理文件或目录 | Win32；猜 Explorer 落点 |
| `SafetyRoot` | 远端 `check_descendant` | 本机路径策略 |

### 2.2 拖入命中规则

事件是整窗的（wry）。只在 **文件模块已挂载** 时处理：

- 无在线选中设备 → 忽略。
- 落点不在文件页内容区（列表、空白、面包屑）→ 忽略。
- 落在**目录行** → 远端 = `childPath(session.path, dir.name)`。
- 落在文件行 / 列表空白 / 面包屑当前段 → 远端 = `session.path`。
- 每个被丢的本机顶层路径（文件或目录）一次 `files.push`。`adb push` 自己递归目录。

保持 `tauri.conf.json` 不关 `dragDropEnabled`（默认 true）。关掉会回到 HTML5 drop，Windows 上没有完整路径。

### 2.3 拖出协议

对标 Shell `CFSTR_FILEDESCRIPTOR` + `CFSTR_FILECONTENTS`（[文档](https://learn.microsoft.com/en-us/windows/win32/shell/datascenarios)）。**禁止**先全量 pull 再交 `CF_HDROP`。

```text
FileTable dragstart
  → preventDefault
  → files.dragOut({ serial, remotes: [绝对远端路径…] })
  → dnd 在主线程 DoDragDrop(COPY)
       QueryGetData / DragEnter：只给描述符，不 pull
       IAsyncOperation：允许 Explorer 后台抽取
       GetData(FileContents, lindex)：
         TransferRunner.pull → %LOCALAPPDATA%\YohuAdbTools\data\modules\file-manager\drag-out\<id>\
         返回 IStream（STGM_DELETEONRELEASE）
  → Explorer 自己写用户松开的文件夹
```

约束：

- 只报 `DROPEFFECT_COPY`。
- 目录项：`FILEDESCRIPTOR` 带目录属性，无 contents；子文件各一条，相对路径用 `\`。
- Windows 非法名（`<>:"/\|?*`、尾空格/点、保留设备名）在 `dnd` 过滤，不进入描述符。
- 取消 / 失败：**不**删 Android 源。临时文件随流释放或下次拖出/退出时清 `drag-out\`。
- 落到本窗：wry 只认 `CF_HDROP`，虚拟格式会被忽略。一期不支持应用内拖放。

### 2.4 公开 API

现有：

- `files.push` / `files.pull` `{ serial, local, remote }` — 语义扩展为 local/remote 可为文件或目录。
- `files.cancel`、`transfer.progress` — 不变。

新增：

- `files.dragOut` `{ serial, remotes: string[] }` → `()`（`DoDragDrop` 结束后返回）。id 仍由壳为每一次内部 pull 发号，进度走已有事件。

不新增「dropIn」命令：拖入走已有 `files.push`。

### 2.5 临时目录

架构文档 §10.1 已留 `modules/file-manager/`。拖出专用：

```text
DataRoot/modules/file-manager/drag-out/<drag-session-id>/
```

启动与退出序列清残留。不写到 `%TEMP%` 根目录。

## 3. 设计后链路

### 3.1 拖入（Explorer → 设备）

```text
Explorer CF_HDROP
  → wry IDropTarget（子 HWND；AllowExternalDrop=false）
  → tauri://drag-enter|over|drop|leave  { paths, position }
  → FileView：命中测试
  → fileStore.push(localPath, basename) × N
  → 其后与对话框上传同一条 TransferRunner 链
  → 终态后 refresh 当前目录
```

### 3.2 拖出（设备 → Explorer）

```text
选中行 dragstart
  → files.dragOut
  → dnd 虚拟 IDataObject（描述符树）
  → 用户在 Explorer 松开
  → Explorer GetData(FileContents[i])
  → TransferRunner.pull（SafetyRoot + 进度事件 + 可取消）
  → IStream → Explorer 写目标
```

对话框开/存仍走原链，与拖拽共享 `TransferRunner`。

## 4. 对现有模块的影响

| 位置 | 变化 |
|------|------|
| `core/yohu-files/transfer.rs` | push 接受文件或目录；pull 取消/失败时目录走 `remove_dir_all` |
| `core/yohu-files/browse.rs` | 三期：`list_tree`（安全根下递归，供描述符展开）。一期拖出文件可不做 |
| `app/yohu-app/src/dnd/` | **新建**；`lib.rs` 组装 |
| `commands/files.rs` | 增加薄 `files.dragOut`；push/pull 签名不变 |
| `yohu-protocol` | `DragOutRequest`；`TransferRequest` 不变 |
| `@yohu/api` | `filesDragOut` + 契约测试 |
| `FileView` / `FileTable` / `store` | drop 监听、命中纯函数、overlay 配方、行 draggable |
| `tauri.conf.json` | **不改** `dragDropEnabled` |
| 终端 / 日志 / 设置 | 不改 |

`commands/*` 仍不得出现 Win32 OLE 类型。`dnd` 是与 `sidecar.rs` 同级的壳模块。

## 5. 分期

| 期 | 用户路径 | 代码 |
|----|----------|------|
| **P1 拖入** | 从 Explorer 把文件或文件夹丢进当前目录 / 目录行 | wry 事件 + 命中 + `TransferRunner` 目录 + overlay |
| **P2 拖出文件** | 从列表把文件拖到 Explorer | `dnd` 虚拟 `IDataObject` + GetData 才 pull；仅 Copy |
| **P3 拖出目录** | 文件夹整棵描述符树 | `browse.list_tree` + 多 lindex |

P1 可单独验收。P2 不依赖本机双栏。P3 不阻塞 P2。

## 6. 不做什么

- 本机文件树 / FileZilla 双栏（Explorer 已是本机侧）。
- 关 `dragDropEnabled` 改用 HTML5 `ondrop`。
- `tauri-plugin-drag` / Electron `startDrag` 式 `CF_HDROP` 预物化。
- 用窗口标题嗅探 Explorer 当前路径再 `adb pull` 到该处。
- Move / 剪切拖拽；拖出成功后删 Android 源。
- `.apk` 丢进窗口即 `adb install`（那是 scrcpy 投屏语义）。
- MTP / 盘符挂载 / adbfs。
- 应用内拖放到另一目录（可后续用私有格式；不进 v1）。
- 在 `@yohu/ui` 做通用 DnD 组件库；文件页用现有 token / overlay 配方即可。
- core 引用 `windows` / Tauri OLE。

---

## 7. 验收要点

- P1：丢文件、丢文件夹、丢到目录行、丢到日志页被忽略、无设备忽略、非法远端由 core 拒绝；进度卡与对话框上传一致。
- P2：拖出过程中资源管理器不出现 0 字节占位（描述符可先到，内容在 GetData 后）；取消不删设备文件；大文件时窗口可动（`IAsyncOperation`）；进度走任务中心。
- P3：文件夹在 Explorer 里展开为目录树，而非单个空文件夹。
- 真机：与现有 `yohu-files` 真机用例同级；无设备环境跳过。
- 启动一次窗口核对命中高亮（windows-desktop 类型包）。

## 8. ADR-v6-018

**决策：** Explorer 双向拖拽拆成「wry 拖入 + 壳虚拟文件拖出」；传输仍只经 `TransferRunner` + `SafetyRoot`。

**理由：**

1. WebView2 窗口化控件上，wry 已接管 `IDropTarget` 并关闭 HTML5 文件 drop。拖入应复用 `tauri://drag-drop` 的绝对路径，而不是再注册一层 OLE。
2. `CF_HDROP` 只能描述已存在的本机文件。设备文件必须用 `FILEDESCRIPTOR`/`FILECONTENTS` 延迟渲染；GetData 之前 pull 会得到空文件或卡死拖动手势。
3. Explorer 不把落点路径回给源。拖出不能变成「pull 到用户悬停的那个文件夹」。
4. OLE 是 Windows 壳胶水，不是领域。放进 core 违反 ADR-v6-005；放进 `commands/*` 违反薄命令层。

**否决：** 预 pull + `drag-rs`；关 Tauri drop 改 HTML5；双栏本机浏览；v1 Move。
