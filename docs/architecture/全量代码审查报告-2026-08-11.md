## 1. 执行摘要

v5 模块化单体已基本落地（分层、贡献点、NetArchTest、部分单测），整体方向正确。但存在若干会**直接导致功能失效、进程泄漏或危险操作绕过**的缺陷，应在下一迭代优先修复。

| 级别 | 数量 | 顶风险 |
|------|------|--------|
| P0 / Critical | 3 | logcat 停后再启失效；流式取消不杀进程；删除路径可穿越安全根 |
| P1 / High | 5 | 文件操作后列表不刷新；退出不清采集；`File.Replace` 首写失败边角；data.root 与 Refresh 矛盾；全局异常一律吞掉 |

| P3 / Low | 7 | 次要资源/语义问题 |

**建议修复顺序：** C1 → C2 → C3 → H1 → H2 → H3/H4 → 其余。

## 2. Findings

### Critical / P0

#### [C1] logcat 停止后无法再次采集（Channel 一次性关闭）

- **位置：** `src/Modules/Yovo.Modules.LogAnalyzer/Application/LogcatCaptureService.cs`（约 20、106）；`LogAnalyzerViewModel.DrainLoopAsync`（约 158–188）
- **证据：** `_lines` 为字段级 `Channel`；`ConsumeLoopAsync` 的 `finally` 调用 `_lines.Writer.TryComplete()`；`StartAsync` 不重建 Channel；`DrainLoopAsync` 仅在 VM 构造时启动一次，`WaitToReadAsync` 在通道完成后永久结束。
- **影响：** 用户「停止 → 再开始」后进程可能启动，但 UI 行流永久中断，模块表现为采不到日志。
- **修复：** 每次 `StartAsync` 新建 Channel 并通知消费端重启 Drain；或 Stop 时不 Complete Writer，改用世代 token。

#### [C2] 流式进程取消/Dispose 不 Kill → adb 孤儿进程

- **位置：** `src/Yovo.Platform/Process/ProcessRunner.cs`（`StreamingProcess.DisposeAsync` 约 196–200；`StartStreamingAsync` 约 58–66）；`AdbClient.TransferAsync`（约 64–87）；契约 `IProcessRunner` / `ProcessSpec.KillTreeOnCancel`
- **证据：** 文档约定「取消 = Kill」；`KillTreeOnCancel` 在实现中**未被读取**；`StartStreamingAsync` 忽略传入的 `CancellationToken`；`DisposeAsync` 仅 `_process.Dispose()`，不 `Kill(true)`；`TransferAsync` 在 `WithCancellation` 中断后靠 `await using` Dispose，不显式 Kill。
- **影响：** 取消 push/pull 或中断流式命令后 adb/子 shell 可能残留，占用设备与端口，拖垮后续 ADB。
- **修复：** Dispose/取消路径统一 `Kill(true)`；`ct.Register(Kill)`；落实 `KillTreeOnCancel`。

#### [C3] 文件删除「安全根」可被路径穿越绕过

- **位置：** `src/Modules/Yovo.Modules.FileManager/Domain/RemotePath.cs`（`Combine` 约 46–49；`IsSafeForDestructiveOps` 约 53–55）；`FileManagerViewModel.CreateDirectoryAsync` / `DeleteAsync`
- **证据：** `Combine("../../../data")` → `/sdcard/../../../data`；`StartsWith("/sdcard")` 仍为 true；随后 `rm`/`mkdir` 由 shell 解析真实路径。目录名来自用户输入，无 `..` / `/` 校验。另：等于 `/sdcard`、`/storage` 自身也被视为安全。
- **影响：** 在「仅允许用户存储区」前提下仍可能对安全根外路径做危险操作（产线设备上为高危）。
- **修复：** 规范化并解析 `..`；拒绝含 `..` 或绝对段的 name；安全检查基于规范化绝对路径，且要求**严格子路径**（禁止等于安全根）。

### High / P1

#### [H1] 上传/删除/新建后 `RefreshAsync` 因 `IsBusy` 直接跳过

- **位置：** `FileManagerViewModel.RefreshAsync`（约 75–76）；`UploadAsync` / `DeleteAsync` / `CreateDirectoryAsync` 成功路径中的 `await RefreshAsync()`
- **证据：** 外层已 `IsBusy = true`，内层 `if (... || IsBusy) return;`，成功路径上的刷新恒为 no-op。
- **影响：** 操作成功后列表陈旧，易误判失败或重复操作。
- **修复：** 拆分「加载锁」与「传输锁」，或提供内部 `RefreshCoreAsync` 强制刷新。

#### [H2] 应用退出不停止 logcat / 未挂接 ShutdownToken

- **位置：** `LogAnalyzerModule.DisposeAsync` 空实现；`LogAnalyzerViewModel` 未订阅 `IAppLifecycle.ShutdownToken`；`App.OnExit` 虽 Cancel CTS + 调用模块 Dispose，但模块 Dispose 为空
- **证据：** 契约注释要求长任务链入 `ShutdownToken`；采集 CTS 仅来自 VM 本地。
- **影响：** 关主窗口后 adb logcat 可能残留；与 C2 叠加更严重。
- **修复：** `DisposeAsync` / Shutdown 时 `Stop()` + Complete 后台任务；传输任务同样挂接。

#### [H3] `CommandRepository.SaveAsync` 在目标不存在时用 `File.Replace` 会失败

- **位置：** `CommandRepository.SaveAsync`（约 78）；对比 `SettingsStore` 有 `Exists ? Replace : Move`
- **证据：** `File.Replace` 要求目标已存在。`LoadAsync` 在 `IOException` 时返回内置库且**不写盘**；若此后用户保存，必失败。首次路径虽常有 `TryWrite`，边角仍破。
- **影响：** 特定加载失败后命令库无法落盘。
- **修复：** 与 `SettingsStore` 相同：不存在则 `Move`，存在则 `Replace`。

#### [H4] 修改 `data.root` 后立即 `ToolResolver.Refresh()`，与「重启生效」矛盾

- **位置：** `AppPaths.DataRoot`（惰性读设置）；`SettingsViewModel.Save`（约 81–85）；`ToolResolver.ResolveAdb` 使用 `_paths.ToolsRoot`
- **证据：** UI 文案写数据目录重启生效，但 Save 后 `Refresh()` 清缓存；无 adb 覆盖时下次 Resolve 指向**新** `ToolsRoot`（可能空），ADB 瞬时不可用，旧目录数据仍在。
- **修复：** DataRoot 启动时冻结快照；或 Save 时不对 tools 因 DataRoot 变更而 Refresh。

#### [H5] 全局 `DispatcherUnhandledException` 一律 `Handled = true`

- **位置：** `Yovo.Host/App.xaml.cs`（约 30–45）
- **证据：** 任意未处理 UI 异常写 crash 日志后继续跑。
- **影响：** 状态半损坏后界面仍「可用」，后续二次故障更难查。
- **修复：** 仅对已知可恢复异常 Handled；其余提示后退出或限制操作。

## 3. 正向观察

1. **依赖方向清晰：** Host → Shell/Modules → Platform → Abstractions；NetArchTest 强制模块互不引用。  
2. **ADB 成败分离：** 判定在 `CommandEvaluator`，平台只出原始结果。  
3. **设备模型：** Directory 与 SessionHub 分离，符合 v5 设计。  
4. **命令管理：** 深拷贝编辑 + 脏关闭确认；损坏备份思路正确。  
5. **日志边界：** 模块注释明确禁止把 logcat 写入 `IAppLog`（ADR-006）。  
6. **可测性：** 文件删除确认回调注入；Evaluator / SessionHub / 部分 Execution 有单测。

## 5. 架构与仓库债务

1. **生命周期未闭环：** `ShutdownToken` 已注入，业务长任务未统一挂接；多模块 `DisposeAsync` 为空。  
2. **进程契约与实现漂移：** 文档承诺取消即杀树，流式路径未兑现。  
3. **贡献点部分空壳：** StatusItem / DeviceAction / Command 等注册 API 存在，Shell 主要消费 Navigation + Settings。  
4. **旧代码残留：** `src/FactoryHelper/` 与 v5 并存，易造成审查/构建混淆，应删除或移出主解决方案。  
5. **设置热更新语义分裂：** adb.path「立即」、data.root「重启」，但 `AppPaths` 惰性读破坏约定（H4）。
