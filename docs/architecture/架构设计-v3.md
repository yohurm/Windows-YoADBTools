# Yovo ADB Tools — 平台架构设计 v3

> 定位：**多模块桌面工具平台**。ADB 命令收发终端仅是其中一个功能模块，
> 后续可扩展投屏显示、文件管理、日志分析等模块。
> 原则：一个命令，一个模型，一处定义，处处一致；一个平台，模块插拔，共享服务。

---

## 1. 平台总体架构

```
┌──────────────────────────────────────────────────────────┐
│  Host 平台层（Yovo ADB Tools Shell）                      │
│  ┌────────────────────────────────────────────────────┐  │
│  │  Shell (MainWindow)                               │  │
│  │  ┌──────────────┐ ┌─────────────────────────────┐ │  │
│  │  │ 模块导航栏     │ │ 模块内容区 (ContentControl) │ │  │
│  │  │ ADB命令终端    │ │  当前激活模块的 View         │ │  │
│  │  │ 投屏显示 [预留] │ │                             │ │  │
│  │  └──────────────┘ └─────────────────────────────┘ │  │
│  └────────────────────────────────────────────────────┘  │
│  核心框架: ModuleRegistry / IModule / Shell 导航          │
│  共享服务: AdbService(设备连接) / LogService / Settings   │
├──────────────────────────────────────────────────────────┤
│  Module: AdbTerminal（ADB 命令终端 — 当前已实现）          │

└──────────────────────────────────────────────────────────┘
```

### 1.1 模块接口（平台扩展点）

```csharp
/// <summary>模块契约 — 平台只认识这个接口，模块插拔的扩展点</summary>
public interface IModule
{
    /// <summary>模块唯一标识（如 "adb-terminal"）</summary>
    string Id { get; }

    /// <summary>导航栏显示名（如 "ADB 命令终端"）</summary>
    string Title { get; }

    /// <summary>导航栏图标资源键（如 "IconTerminal"）</summary>
    string IconKey { get; }

    /// <summary>模块初始化（注入平台服务）</summary>
    void Initialize(IModuleContext context);

    /// <summary>创建模块主视图</summary>
    UserControl CreateView();
}

/// <summary>模块上下文 — 平台向模块暴露的能力</summary>
public interface IModuleContext
{
    /// <summary>共享设备连接服务（投屏模块同样需要 ADB 连接）</summary>
    IAdbService Adb { get; }

    /// <summary>共享日志服务</summary>
    ILogService Log { get; }

    /// <summary>配置存储（按模块 Id 分命名空间）</summary>
    ISettingsService Settings { get; }
}

/// <summary>模块注册表 — 启动时登记模块，Shell 自动生成导航</summary>
public class ModuleRegistry
{
    void Register(IModule module);
    IReadOnlyList<IModule> Modules { get; }
}
```

### 1.2 新增模块的方式（扩展性验证）

```
1. 新建文件夹 src/FactoryHelper/Modules/ScreenMirror/
2. 实现 ScreenMirrorModule : IModule（CreateView 返回投屏界面）
3. App.xaml.cs 注册: registry.Register(new ScreenMirrorModule(context))
4. 完成 — Shell 导航自动出现"投屏显示"，无需改动其他模块
```

### 1.3 共享服务（平台级，跨模块复用）

| 服务 | 职责 | 使用者 |
|------|------|--------|
| `AdbService` | ADB 进程管理、设备扫描/连接状态 | 所有模块（终端/投屏/文件管理） |
| `LogService` | 事件驱动日志 | 所有模块 + Shell |
| `SettingsService` | 按模块命名的配置存储 | 所有模块 |

> 注意：设备连接是**平台级共享**的。投屏、文件管理都要基于同一设备连接，
> 所以 `AdbService` 归属平台层，模块通过 `IModuleContext.Adb` 获取。

## 2. AdbTerminal 模块内部架构（继承 v2 统一设计）

### 2.1 统一命令模型 `CommandDefinition`

单条命令与命令组步骤**合并为同一模型**：

```csharp
public class CommandDefinition
{
    string Id;
    string Name;             // 显示名
    string? Category;        // 标签分组（单条命令用）

    string Command;          // 模板，支持 {0} {1} 占位符
    List<string> InputPrompts;   // 输入提示

    int TimeoutMs;
    string? SuccessRegex;    // 输出匹配即成功（bdft 退出码 255）
    string? FailureRegex;    // 输出匹配即失败（优先级最高）

    int DelayAfterMs;        // 组步骤延时（单条命令忽略）
    bool StopOnFail;         // 组步骤失败中断（单条命令忽略）

    string DisplayCommand => $"adb {Command}";   // 全站统一显示
    bool RequiresInput => InputPrompts.Count > 0;
}
```

**消除**：`AdbCommand`、`GroupStep`、`AdbCommandEditable`、`GroupStepEditable` 四文件 → 只剩 `CommandDefinition`。

**统一渲染**：主列表 / 日志 / 管理窗口 / 输入区标题全部用 `DisplayCommand` 与 `Name`，一处定义处处一致。

### 2.2 单一数据源 `CommandLibraryService`

```csharp
public class CommandLibraryService
{
    List<CommandDefinition> SingleCommands;   // 单条命令库
    List<CommandGroup> Groups;                // 命令组（步骤即 CommandDefinition）
    List<string> Tags;

    // CRUD 唯一入口，改完触发 LibraryChanged 事件，界面自动刷新
    event Action? LibraryChanged;
}
```

主界面与管理窗口共用 DI 单例，**不再有"保存后传回手动刷新"**。

### 2.3 执行引擎 `ExecutionService`

- `ExecuteAsync(serial, CommandDefinition)` — 单条
- `ExecuteGroupAsync(serial, CommandGroup, onStepCompleted)` — 组（步骤级进度回调，实时日志）
- 参数解析 / 深拷贝 / 占位符替换收敛在引擎内部

### 2.4 设备选择同步

用 `SelectedItems` 附加行为绑定到 VM，移除 code-behind 手动同步。

## 3. 迁移步骤

| 步骤 | 内容 |
|------|------|
| 1 | 平台框架：`IModule` / `IModuleContext` / `ModuleRegistry` / Shell 导航改造 |
| 2 | 共享服务拆分：`AdbService` 平台化、`LogService`、`SettingsService` |
| 3 | `CommandDefinition` 统一模型，删除 4 个旧模型文件 |
| 4 | `CommandLibraryService`（单一数据源 + 变更事件） |
| 5 | `ExecutionService` 独立执行引擎 |
| 6 | AdbTerminal 模块化：现有功能收拢为模块，绑定全部统一 |
| 7 | 管理窗口重写（直接调 CommandLibraryService） |
| 8 | 构建、真机回归（设备扫描/单条/命令组/写入SN/输入区/标签/脏检查） |
